# Status Skill

Inspect the `.dev/` directory to show the current state of all work items and suggest the next logical step.

## Instructions

1. **Check for `.dev/` directory** — if it doesn't exist, report that no work items are active and suggest starting with `/brainstorm` or `/plan`.

2. **Scan work items** — for each subdirectory in `.dev/` (excluding `scratch.md`):
   - Read the directory name to determine type and slug (e.g., `feat-auth-flow` → type: feat, slug: auth-flow)
   - Check which files exist: `research.md`, `plan.md`, `tasks.md`, `scratch.md`, `reviews/`

3. **Determine the state source — read the footer first, before any inference.** This is the primary path (`templates/handoff-footer.md`, task 4.2); the lane/phase inference in steps 4–5 is a fallback, not the default.

   - Check the work item's artifacts for a trailing fenced `loadout-handoff` block, in this priority order (most-advanced artifact first, since it reflects the item's current state): `reviews/review-<N>.md` (highest N) → `tasks.md` → `plan.md` → `research.md` → `brainstorm.md`. Use the first one found that ends in the block.
   - Extract it with a fence-bounded scan, no prose reading required:
     ```
     awk '/^```loadout-handoff$/{f=1;next} /^```$/{f=0} f' <file>
     ```
   - **Footer present → authoritative, no content sniffing.** Read `lane`, `verification`, `next_command`, `next_arguments`, and `artifact` straight from the block's `key: value` lines. These values are used as-is for the work item's lane and next-step suggestion — do **not** also run the express-marker check or the `**TDD Gate**` scan in step 4; the footer already replaces them (`templates/handoff-footer.md`'s `lane` key note). Record this work item's state source as **`from footer`**.
   - **No footer on any artifact → legacy fallback.** This is expected for any `.dev/<slug>/` work item created before this schema existed. Fall through to steps 4–5 below unchanged. Record this work item's state source as **`inferred (legacy, no footer found)`**.
   - Either way, always report which source was used (see the output format in step 8) — never leave it implicit.

4. **[Legacy fallback — footer-less work items only] Determine lane** — check in this order (first match wins):

   - **Express lane** (`/perform-task`) — either:
     - `plan.md` exists and its first line is the marker `> Generated by /perform-task — prompt-as-plan` (the exact marker `perform-task` writes as required by its `## Rules` section in `skills/perform-task/SKILL.md`), or
     - `plan.md` and `research.md` both do **not** exist, but `scratch.md` does (and possibly `reviews/`) — the transient shape of an express item mid-flow, since `perform-task` scaffolds `scratch.md` (Step 2) before writing `plan.md` (Step 3). Report this as the express lane in progress, **not** as "missing plan.md".
   - **TDD lane** (`/tdd-plan` → `/tdd-build`) — `plan.md` exists and contains a `**TDD Gate**:` block or a `## TDD Gate Summary` heading (the exact markers `tdd-plan` writes; see `skills/tdd-plan/SKILL.md`'s "Canonical TDD Gate Format").
   - **Standard lane** — everything else (a `plan.md` with neither the express marker nor TDD Gates, or no `plan.md` at all).

5. **[Legacy fallback — footer-less work items only] Determine phase**, using the table for its lane:

   **Standard lane**

   | Files Present | Phase | Suggested Next Step |
   |--------------|-------|-------------------|
   | Nothing | Initialized | `/brainstorm <slug>` or `/plan <slug>` |
   | `research.md` only | Researched | `/plan <slug>` |
   | `plan.md` (no `reviews/`) | Planned | `/build .dev/<type>-<slug>` |
   | `plan.md` + active changes, no `reviews/` | Building | Continue building or `/review .dev/<type>-<slug>` |
   | `reviews/` exists, open findings | In Review | `/review-fix .dev/<type>-<slug>/reviews/review-<N>.md` |
   | `reviews/` exists, no open findings | Complete | `/triage .dev/<type>-<slug>` to promote insights |

   **TDD lane**

   | Files Present | Phase | Suggested Next Step |
   |--------------|-------|-------------------|
   | `plan.md` with TDD Gates, no `reviews/` | TDD Planned | `/tdd-build .dev/<type>-<slug>` — **not** `/build` |
   | `plan.md` with TDD Gates + `reviews/`, open findings | TDD Built | `/review .dev/<type>-<slug>` |
   | `reviews/` exists, no open findings | TDD Reviewed | `/triage .dev/<type>-<slug>` |

   **Express lane**

   | Files Present | Phase | Suggested Next Step |
   |--------------|-------|-------------------|
   | `scratch.md` only, no `plan.md`, no `research.md` | Express In Progress | flow is mid-run; re-run `/perform-task <description>` if it stalled |
   | `plan.md` (perform-task marker), no `reviews/` | Express Built | `/review .dev/<type>-<slug>` |
   | `plan.md` (perform-task marker) + `reviews/`, no open findings | Express Reviewed | `/triage .dev/<type>-<slug>` |

6. **Check for global scratch** — if `.dev/scratch.md` exists, note it has cross-cutting observations.

7. **Check `.ai-docs/`** — report if the knowledge base exists and how many documents it contains.

8. **Format output** — always include the state source line so it's clear whether a work item's lane came from the footer or from inference:

```
## Loadout Status

### Knowledge Base
- `.ai-docs/`: [N documents | not initialized — run /init-docs]

### Active Work Items

#### [type]-[slug] — [Phase]
- State source: [from footer | inferred (legacy, no footer found)]
- Lane: [Standard | TDD | Express]
- Research: [exists/missing]
- Plan: [exists/missing]
- Scratch: [N entries / empty / missing]
- Reviews: [N iterations / none]
- **Next step**: [suggestion]

### Global Scratch
- [exists with N entries / not present]

### Suggested Actions
- [Most impactful next action based on current state]
```

If "$ARGUMENTS" specifies a slug, show detailed status for just that work item (including file summaries). Otherwise show the overview for all work items.
